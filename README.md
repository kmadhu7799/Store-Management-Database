# 🛒 Grocery Store Management & Sales Analytics — SQL Project

## 📌 Project Overview

The **Grocery Store Management & Sales Analytics** project is a MySQL-based relational database project designed to manage and analyze grocery store operations.

The project demonstrates how SQL can be used to build a structured relational database and generate meaningful business insights from customer, product, order, supplier, and employee data.

The analysis focuses on understanding **customer purchasing behavior, product performance, sales trends, supplier contribution, employee performance, and order-level patterns**.

---

## 🎯 Project Objectives

The main objectives of this project are to:

* Design and implement a relational grocery store database.
* Establish relationships between multiple business entities using Primary Keys and Foreign Keys.
* Analyze customer purchasing behavior.
* Identify top customers based on order volume and purchase value.
* Analyze product performance and category-level pricing.
* Evaluate sales and order trends over time.
* Identify high-performing suppliers.
* Analyze employee order-handling and sales performance.
* Perform detailed order-level analysis.
* Generate business insights using SQL queries.

---

## 🗂️ Database Structure

The database is named:

```sql
GSMDB
```

The project contains **7 relational tables**:

| Table           | Purpose                                                 |
| --------------- | ------------------------------------------------------- |
| `supplier`      | Stores supplier information                             |
| `categories`    | Stores product category information                     |
| `employees`     | Stores employee information                             |
| `customers`     | Stores customer information                             |
| `products`      | Stores product and pricing information                  |
| `orders`        | Stores customer order information                       |
| `order_details` | Stores individual products and quantities within orders |

## The database relationships are implemented using **Primary Keys and Foreign Keys**, with cascading update/delete rules where required.

## 🏗️ Database Schema

### Core Entities

```text
Supplier
   │
   └── Products
          │
          ├── Categories
          │
          └── Order_Details
                    │
                    └── Orders
                         ├── Customers
                         └── Employees
```

### Relationship Overview

* One supplier can provide multiple products.
* One category can contain multiple products.
* One customer can place multiple orders.
* One employee can handle multiple orders.
* One order can contain multiple order details.
* One product can appear in multiple order details.

# 📊 Business Analysis

The project contains several business-focused SQL analysis sections.

## 1️⃣ Customer Insights

The customer analysis answers questions such as:

* How many unique customers have placed orders?
* Which customers have placed the highest number of orders?
* What is the total purchase value per customer?
* What is the average purchase value per customer?
* Who are the top 5 customers by total purchase amount?

For example, customer purchase analysis combines the `customers`, `orders`, and `order_details` tables using JOIN operations and aggregates purchase values using `SUM()` and `AVG()`.

### Business Value

This analysis can help a grocery business:

* Identify high-value customers.
* Understand customer purchasing behavior.
* Identify frequent customers.
* Support customer retention strategies.
* Prioritize high-value customer segments.

The script creates and selects the database:
